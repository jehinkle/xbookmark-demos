Why I stopped writing SAS macros for every table

Dev Patel · September 14, 2026 · 12 comments

For years my reflex for any new summary table was a new macro with fifteen parameters. It felt reusable. In practice, each macro was used for exactly one study and debugged by exactly one person: me.1

What I do instead

Now I keep the derivation in a tidy analysis dataset and let a small, boring reporting step do the layout. In R that looks like this:

adsl |>
  group_by(TRT01A) |>
  summarise(n = n(), mean_age = mean(AGE))

The table code becomes so short that a macro would add more complexity than it removes. The statistic is still simple: the mean is x¯=1n∑xi.

  • Derivations live in ADaM, reviewed once.
  • Layout code is disposable.
  • Double programming compares datasets, not RTF files.
